# Fixtures

Real data used by the tests, so the frontend is checked against what the backend and the overview producer really emit.

| File | What it is | Source |
|---|---|---|
| `flask-detail.json` | Backend `GET /dfd` output (`group_by=directory`) | `pallets/flask` (BSD-3-Clause) |
| `voting-detail.json` | Backend `GET /dfd` output (`group_by=directory`) | `dockersamples/example-voting-app` (Apache-2.0) |
| `voting-files.json` | The config files the overview reads (compose, Dockerfiles, manifests), verbatim | `dockersamples/example-voting-app` (Apache-2.0) |
| `catalog-golden.json` | Answers of the backend's `classify()` for about 1,200 probes | generated, see `docs/dfd-schema.md` |

The two `*-detail.json` files are generated by running the backend against the repository and keeping the response
(`meta.generated_at` fixed so the files stay stable). Regenerate them when the backend's schema changes.
